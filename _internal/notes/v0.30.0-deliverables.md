## 3. 占位符清单（需你手动填写后才能正式收费）

| 占位符 | 当前值（代码位置 `www/index.html` ~L10889-10890） | 动作 |
|---|---|---|
| `K_PAYPAL_LINK` | `https://www.paypal.com/ncp/payment/TODO_REPLACE_WITH_YOUR_LINK` | 替换为你的真实 PayPal 收款链接（PayPal.me 或 NCP Payment Link） |
| `K_SUPPORT_EMAIL` | `TODO_REPLACE_WITH_YOUR_EMAIL` | 替换为你的客服邮箱（用于已付款用户发邮件解锁 + 解锁码错误时的兜底联系） |

**首批 unlock code 示例（格式 `SINOKY-` + 8 位数字，本地正则 `^SINOKY-\d{8}$` 即放行）：**

```
SINOKY-20261015
SINOKY-38172940
SINOKY-00000001
SINOKY-77778899
SINOKY-12345678
```

> ⚠️ 安全提示：当前 code 是**客户端正则放行**，任意 8 位数字组合均可解锁（10⁸ 量级，猜测风险低，但非生产级安全）。上线收费前建议：① 在服务端（Workers + KV）维护一份有效 code 清单并校验；② 记录已兑换 code 防重复使用；③ PayPal 收款后人工/自动邮件确认再置 `sinoky_unlocked`。本方案按 spec「手动收款 + code」交付，服务端加固属后续项。

## 5. 已知问题与后续建议

1. **占位符未填**：`K_PAYPAL_LINK` / `K_SUPPORT_EMAIL` 为 TODO，未填前 PayPal 按钮/邮件会指向无效地址。→ 上线前必填。
2. **解锁安全性**：code 为客户端正则放行，无服务端校验/防复用。→ 见第 3 节建议。
3. **徽章名称/条件未 i18n**：9 徽章名 + 9 条件句为英文 literal（沿用既有徽章名不翻译的约定）。→ 后续统一 i18n 轮次。
4. **`Spaced repetition` 残留 3 处**：行 1156 / 5909 / 6803 为非 Explore 上下文（复习卡描述 / Nono 提示），spec 仅将 Explore 页该词改为 `Smart review (never forget)`。是否一并替换请你定夺——若替换，建议整词改为 `Smart review` 以保持叙事一致。
5. **`dim_sum_master` 用全局音调精度近似**：spec 要求"该场景 tone ≥ 80%"，但产品无按场景音调统计，当前用全局 `S.tone.right/S.tone.total ≥ 0.8` 近似。精准化需先加按场景音调埋点。
6. **视觉效果未做截图回归**：冒烟仅保证"无 JS 错误 + 逻辑正确"，未做像素级视觉核对（尤其 P2 City Map 大卡片视觉权重、P4 灰度/锁标观感）。→ 建议补一次人工/截图走查。
7. **解锁为本地态**：unlock 写入 `localStorage`（`sinoky_unlocked`），清缓存/重装即失效——符合 spec「手动收款+code」定位，但非账号级持久。云端账号同步属本轮不做项。
8. **完整手动走查建议**：onboarding → Home → City Map 大卡片 → 进场景 → ? 帮助 → Progress 页徽章分组 → Me 页 Unlock 输入 code → quota 变 3 倍 → Practice 页入口收敛。自动化已覆盖逻辑，端到端 UX 仍建议人工过一遍。
