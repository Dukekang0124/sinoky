# 诺诺（Nono）接入免费大模型 · 中文自由对话

> 调研 + 设计方案（v0.14.6 之后候选功能）
> 结论先行：**技术上完全可行，且 90% 的零件诺诺和 Worker 已经是现成的，要新写的只有「调大模型」这一环。**
> 红线（Edify Gate 最高优先级）：**必须让「说」成为主路径** —— 默认语音输入（ASR），诺诺语音输出（TTS），文本输入只作无障碍兜底。否则就退化成「中文阅读器」，背离「让用户多说中文」的核心目标。

---

## 一、可行性结论

| 维度 | 现状 | 结论 |
|---|---|---|
| 对话触发入口 | 诺诺浮标 `#nono-fab` + 面板 `#nono-panel` 已存在；姿态状态机 `listening/thinking/speaking/cheer/sorry` 已就绪；`nonoRecord()` 复用 `blobToWav`+`asrText` 已通 | ✅ 直接复用，几乎零成本 |
| 语音输入（ASR） | `/api/asr` 走 Whisper `whisper-large-v3-turbo`，前端 `asrText()` 已封装 | ✅ 现成 |
| 语音输出（TTS） | `/api/tts` 多源兜底（Edge→Google→MeloTTS→有道），前端 `speak()` 已封装 | ✅ 现成 |
| 模型接口（新增） | 当前无 LLM 调用；Worker 有 `env.AI` 绑定 + `guardApi`（Origin+限流）对所有 `/api/*` 自动生效 | ⚠️ 唯一新增：新增 `/api/chat`，自动继承限流/防盗 |
| 会话管理 | `S`（localStorage）已存各类进度；`saveState()` 已封装 | ✅ 加 `S.nonoChat` 即可 |
| 免费模型 | 2026 年仍可白嫖（见第二节） | ✅ 有两条免费通道 |

**一句话**：诺诺 = 现成的「耳朵（ASR）+ 嘴（TTS）+ 脸（姿态）+ 记忆（S）」，只差「脑子（LLM）」。补上 `/api/chat` 一个 Worker 端点 + 前端聊天模式，即可上线。

## 二、免费大模型选型（2026 年实测仍可用）

### 方案 A（主）：智谱 GLM-4-Flash —— 永久免费、中文最顺、首响最快
- 模型：`glm-4-flash`（智谱 AI 官方的轻量旗舰，**永久免费、不限 Token、30 并发、128K 上下文、可商用**）。
- 协议：OpenAI 兼容，`Base URL = https://open.bigmodel.cn/api/paas/v4/`（⚠️ **必须带尾斜杠**），`Authorization: Bearer <key>`。
- 免费额度：**永久免费、无 Token 上限**（仅 30 并发限制）。对 27 设备的小产品绰绰有余（每设备一次对话只占 1 并发，且非持续占用）。
- 成本：0 元（永久免费档）。
- 优点（对口语对话最关键的三点）：① **中文口语最顺**（第三方评测「中文天花板」、翻译准确率 94%）；② **首响最快**（实测 ~0.9s 返回 / ~72 tok/s，远快于 Qwen2.5-7B 的 ~1.4s / 53 tok/s——语音对话对延迟极敏感）；③ 支持 **Function Calling / Web Search**，诺诺后续接「查词/纠错工具」更顺。
- 缺点（可控）：需注册免费 API Key（国内手机号实名），存为 Worker 环境变量 `GLM_KEY`，不进仓库（参照现有 `FEEDBACK_TOKEN` 做法）。**康哥已在用 GLM-4-Flash 跑自动化任务，Key 管理/成本控制都现成**，无需新开账号。

### 方案 B（兜底）：Cloudflare Workers AI —— 零密钥、同平台
- 模型：`@cf/qwen/qwen2.5-7b-instruct` 或 `@cf/qwen/qwen3-30b-a3b-fp8`（MoE，便宜）。
- 免费额度：**10,000 Neurons/天**（全模型共享），零信用卡、同账号已绑 `env.AI`。
- 调用：`env.AI.run('@cf/qwen/qwen2.5-7b-instruct', { messages })` —— 和现有 Whisper/MeloTTS 同一套绑定。
- 缺点：中文质量弱于 GLM-4-Flash；Neurons 额度有限（超限报错）。适合兜底/降级，不适合主用。

### 选型策略（对齐现有 TTS 三源兜底哲学）
> **主用 GLM-4-Flash（永久免费、中文最顺、首响最快）→ 失败自动降级 Workers AI Qwen（零密钥兜底）→ 再失败返回温柔降级文案「诺诺有点累了，待会再聊 😴」**，不阻塞练功。

> 备注：上轮曾拟主用 SiliconFlow Qwen2.5-7B，对比后翻案——两者都免费无限、都 OpenAI 兼容，但 GLM-4-Flash 中文口语更顺、首响更快（语音对话命脉）、支持 Function Calling，且康哥已有现成 Key，故**主用改 GLM、去掉 SiliconFlow 第三钥**，密钥管理面反而更小。Qwen3 会输出「思考过程」对口语是噪音，故兜底也不用 Qwen3。

## 三、三大核心模块

### 模块 1 · 对话触发入口（前端）
- **复用**：`#nono-fab` 浮标、`#nono-panel` 面板、`nonoState(st)` 姿态机、`nonoRecord()`/`asrText()`/`speak()`。
- **新增**：面板内「模式切换」——当前手动点浮标进「跟读练习」（`nonoStartPractice`），改为浮标弹出两个入口：**🎙️ 跟读练习** / **💬 自由聊天**。
- **新增 DOM**：`#nono-chat` 聊天区（用户气泡 + 诺诺气泡滚动列表）、**按住说话**大按钮（复用 `nonoRecord` 录制逻辑）、可选文本输入框（无障碍兜底，非默认）。
- **交互默认语音**：进入聊天 → 诺诺 `speaking` 姿态 + TTS 开场白；用户**按住** mic 说话 → `listening` → `thinking`（等 ASR+LLM）→ `speaking`（TTS 回复）。文本输入是折叠的次级入口。

### 模块 2 · 模型接口对接（Worker `/api/chat`）
- **落点**：`_worker.js` 的 `fetch` handler，在 `/api/asr` 之后加分支 `if (url.pathname === '/api/chat')`。**自动继承 `guardApi`（Origin 校验 + 每 IP 60s 限流）**——不用重写防盗。
- **输入**：`{ messages: [{role,content}], uid, level }`（level=学习者等级，可选 HSK1/2）。
- **处理逻辑**：
  1. 拼 system prompt（见第四节 persona）。
  2. 调 GLM-4-Flash（带 `GLM_KEY` 环境变量，base_url 须带尾斜杠）→ 失败 `catch` 降级 `env.AI.run('@cf/qwen/...')` → 再失败返回降级 JSON。
  3. 返回 `{ reply: '<中文>', usage?: {...} }`。
- **流式（可选增强）**：先用 SSE 流式拿 token 降低体感延迟；但 TTS 需整句，故采用**句级 TTS**——拿到完整回复后按句号切分，逐句 `speak()`，首句先播。
- **限流微调**：聊天比跟读更频繁，建议给 `/api/chat` 单独限频（如每用户/IP 20 次/分钟），在 `guardApi` 或本分支内叠加判断，防免费额度被刷。

### 模块 3 · 中文会话管理（前端 + 轻量后端）
- **历史存储**：前端 `S.nonoChat = [{role, content}]`，走现有 `saveState()` 落 localStorage，**跨会话续聊**（刷新/重开不丢）。
- **发送策略**：每次请求带 `system + 最近 N 轮（建议 12 轮）历史 + 用户新句`，控制 token 量；超长则裁剪/摘要旧轮。
- **与发音练习联动（加分项）**：用户说的每句经 ASR 出汉字后，**复用 A 模块声调评分**（`/api/score`，target=用户这句自身当参照或空 target），在气泡下发温柔提示「诺诺听到啦，'吃饭' 的第三声可以再饱满一点 😊」——自由聊天顺便练发音，强化 Edify Gate。
- **安全约束**：system prompt 锁死「只输出简体中文、口语、短句、不跑题、不涉及敏感/成人内容」；可选后处理过滤非中文比例过高的回复。

## 四、诺诺人格 System Prompt（草稿）
```
你是诺诺，一只会中文的熊猫，是外国人的中文陪练伙伴。
- 全程用简体中文、口语、短句（每轮 1~3 句）。
- 用户是中文学习者，用他们能懂的词；生词可附极简拼音，但不要满篇拼音。
- 每轮结尾抛一个开放小问题，引导用户开口说（这是你的核心任务：让用户多说）。
- 不纠正语法错误，除非用户主动问；语气像朋友，不像老师。
- 不输出英文、不使用 Markdown、不列举长文。
- 如果用户说的是英文，用中文温柔鼓励ta试试用中文说。
```

## 五、整体架构（数据流）
```
用户按住 mic
   │  MediaRecorder → blobToWav(16k)
   ▼
/api/asr (Whisper) ──► 汉字文本  ──► 显示用户气泡
   │                                  │
   │                          [可选] /api/score 声调轻评
   ▼                                  ▼
/api/chat (新增)                       │
   ├─ GLM-4-Flash (主, GLM_KEY, 智谱直连)
   └─ Workers AI Qwen (兜底, env.AI, 零密钥)
   │
   ▼  reply(中文)
显示诺诺气泡 ──► /api/tts (多源) ──► speak() 朗读
   │
   └─► 循环回「用户按住 mic」
关闭 → S.nonoChat 落盘，诺诺回 idle
```
所有 `/api/*` 自动过 `guardApi`（Origin + 限流）；密钥走环境变量，不进公开仓库。

## 六、关键设计要点与风险

| 要点 | 设计 | 风险/对策 |
|---|---|---|
| **Edify Gate 红线** | 默认语音输入，文本仅兜底 | 若默认文本=退化成阅读器。**必须语音优先** |
| 端到端延迟 | ASR+LLM+TTS 链式约 2~4s | `thinking` 姿态 + 先播「嗯…」占位 + 句级 TTS；后续上 SSE 流式 |
| 免费额度 | GLM-4-Flash 永久免费不限量（30 并发） | 仍加每用户限频；Workers AI 兜底 10k neurons/天，超限降级文案 |
| 中文质量 | 免费档偶有病句/夹英文 | system prompt 锁中文口语 + 后处理过滤非中文；必要时升级 GLM-4.7/GLM-5（智谱同平台，平滑切换） |
| 安全/内容 | 语言学习场景 | system prompt 约束 + 可选输出审核；不接联网/工具调用 |
| 隐私 | 语音→文本发模型 | 匿名 UID；隐私说明轻量告知「对话用于陪练，不关联身份」 |
| 与跟读练习共存 | 同一面板两种模式 | 用 `NONO.mode` 区分，共用录音/姿态/TTS |
| 存储成本 | 历史存 localStorage | 不写 KV（省写额度）；可选 KV 备份跨设备（低优先） |

## 七、建议实施步骤（落地顺序）
1. **Worker**：加 `/api/chat`（GLM-4-Flash 主 + Workers AI 兜底 + 降级文案），配 `GLM_KEY` 环境变量（base_url 带尾斜杠）；本地 `node --check` + 真浏览器 mock 自测。
2. **前端入口**：面板加「💬 自由聊天」模式按钮 + `#nono-chat` 区 + 按住说话按钮。
3. **前端对话**：`nonoChatSend()` 串 ASR→/api/chat→渲染气泡→TTS；`S.nonoChat` 历史管理。
4. **联动发音**（加分）：用户句过 `/api/score` 出温柔声调提示。
5. **真浏览器自测**：Playwright Chrome + 本地 server + mock `/api/chat`（返回固定中文），验证「点诺诺→说话→气泡→诺诺朗读→续聊→关闭续接」全链路。
6. **发版 SOP**：四处版本同步 → push main → tag 出包 → 回填（与 v0.14.6 同流程）。
