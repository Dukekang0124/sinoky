# Sinoky 大模型「极致」升级方案（免费 GLM-4-Flash 全面渗透）

> 配套：审计报告 `LLM_AUDIT_REPORT.md` + 枚举脚本 `diag_llm_coverage.py`。
> 判据铁律（来自 `llm-capability-coverage-audit`）：**「极致」的真判据不是「机制铺得最多」，而是「可被验证」。一套自己无法被验证的方案，无论多精巧都不叫极致——极致的反面不是「不够多」，是「无法证伪」。**
> 落地铁律（同技能落地篇/再审计篇）：单一追加块 + 全包装（主链零改动）、幂等补丁、独立渲染槽、三件通用件、让 AI 结果**影响下一步行为**、验收先定量再全量回归、运行时抓包证「线通电」。

---

## 一、先定义「极致」——否则方案会滑向自我感动

极致 = 三件事同时成立，缺一个都不算：

1. **铺在用户花时间的地方**（练习主战场），不是易做的闲聊。
2. **每个 AI 动作都闭环**（AI 指出一次错误 → 写回账本 → 下次必排这句），不是弹个气泡就完。
3. **效果可被验证**（L3 服务端可见 + 闭环追踪），不是「我觉得更聪明了」。

本方案以这三条为验收门槛。任何一条达不到，该能力不标记为「已落地」。

## 二、现状基线（从审计报告来，不是推测）

| 层 | 现状 |
|---|---|
| 通用大模型 L1 广度 | **错位**：`/api/chat` 全代码仅 1 处（L4499 `nonoChatReply`），且只在诺诺闲聊；179 用户入口仅 1 个间接触及 |
| 专用评分模型 | 合理：在诺诺跟读(L4548)、场景跟读(L1398)、通用 `sendScore`(L5264) 三处正确布点 |
| 客户端度量 L2 | 扎实：本地 `S.nono` / `S.rev` / `errorProfile` / `bkt` 完整 |
| 服务端度量 L3 | **断**：仅 `badgeReport`(独立徽章服务) + `api/feedback`(意见表单)，无漏斗/留存/学习进度聚合 |
| 用户效果 L4 | **不可知**：样本仅 27 设备 / 47 开口，D1 4.2% ≈ 1 台设备 |

**结论**：不是「再加 AI」，而是「把现有免费大模型挪到对的地方 + 同时修可见性让效果可被证伪」。

## 三、渗透蓝图：把免费大模型织进 7 大学习场景

> 统一调用点 = `/api/chat`（GLM-4-Flash，边际成本≈0）。每个场景只新增一个「出口函数」+ 一个「结果落账」动作，主链零改动（追加块包装）。

### 场景 1 · 跟读评分 → AI 个性化纠正点评（替代规则分支）
- **现在**：`nonoGrade`(L4538) 评分后，点评是规则拼的（`acc>=85 → "说得很好"` 三档分支，L4578–4581）。
- **大模型进**：评分后调用 `/api/chat`，系统提示 = 「你是中文发音教练，基于逐音节结果给用户一句最该改的点 + 一句示范」，输入 `{hz, perSyll, weak}`。
- **闭环**：AI 指出的弱音节写入 `state.aiWeak[line.key]` → 复习排序读它优先排（见场景 2）。
- **多语言**：点评语言跟随 `curLang()`，默认中文透传（入口级指令改写，零行为变化）。

### 场景 2 · 复习引擎 → AI 弱点出题 + 变体句  ✅ **已落地 v0.23.17**
- **现在（v0.23.17 之前）**：`revQueue`/`revSchedule`/`rvMarkError`(L 复习家族) 用 SM-2 + 规则排序，内容来自静态 `SCENES`。
- **大模型进（v0.23.17 落地形态）**：Home 复习卡加「诺诺出的练习句」——取 `S.aiWeak` 最弱维（count≥2 降序）→ `/api/chat mode:'drill'`（`DRILL_SYSTEM` 生成 ≤8 字日常薄弱句，格式 `中文 | English`）→ 存 `S.revDrill`；点开复用 `nonoStartPracticeWith` 开口练，经 `nonoGrade` 自动回灌 aiWeak + 触发 L3 `S.aiFunnel` 闭环。**闭环从「boost 旧句」升级为「造新句练弱点」**。原计划的「变体句进 reviewPool」为更重形态，本期以更轻的「独立薄弱句卡」达成同等闭环，后续可再升级为进队列。
- **闭环**：AI 薄弱句被说出 → `nonoGrade` 计分 → 写回 `S.aiWeak` + `S.aiFunnel.loop`，与点评/情境对话共享同一账本。

### 场景 3 · 场景/情境对话 → AI 扮演对话对手 + 即时纠正  ✅ **已落地 v0.23.18**
- **落地形态（v0.23.18）**：包装 `sendScore`，跟读打分拿到真实 transcript 后调 `/api/chat mode:'scene'`（`SCENE_SYSTEM` 本地人接话），诺诺以场景中人身份自然接一句（可附英文提示），不教学不纠正；软上限 ≤8/天（`S.sceneReplyCap`），面板关闭/忙碌不打扰。闭环：接话本身即"开口延续"，与 L3 `S.aiFunnel` 共享诺诺开口链路。
- **现在**：`openScene`/`renderSceneList`(L 场景家族) 是「Someone says X — you answer Y」脚本对，无真实交互。
- **大模型进**：在「你答完」环节调 `/api/chat`，系统提示 = 「你是对话里的本地人，先用一句中文自然回应，再用英文点出他刚才的用词/语法小问题（如有）」。
- **闭环**：纠正点写 `state.aiWeak`（跨场景累积），下次同场景优先练该点。

### 场景 4 · 每日一句 / 接一句 → AI 生成「属于你的下一句」
- **现在**：`maybeExtendSentence`/`startExtend`(L7511–7543) 让用户自己改词，无引导。
- **大模型进**：基于 `S.nonoChat` 历史 + 已学句型，调 `/api/chat` 建议「你今天可以试说这句（结合你刚聊到的主题）」。
- **闭环**：用户采纳并说出的句子计入 `S.extend` 与 `S.nono.weak`，喂回复习与点评。

### 场景 5 · 字卡 / HSK → AI 生成记忆锚点 + 易混字辨析
- **现在**：`fc*`(L 字卡家族) 只存拼音/释义，无记忆策略。
- **大模型进**：用户收藏一张字卡时，调 `/api/chat` 生成「一个帮你记住它的画面/谐音/例句」，存进卡数据。
- **闭环**：易混字（如 马/妈/骂）由 AI 生成辨析卡，进入复习队列。

### 场景 6 · 声调训练 → AI 用自然语言解释「为什么」
- **现在**：`tone*`(L 声调家族) 只给变调规则与对/错。
- **大模型进**：用户连续错某声调，调 `/api/chat` 生成一句「人话解释」（如「三声像先下坡再上坡，你刚才读成了平调」）。
- **闭环**：解释被收藏进 `state.toneTips[tonenum]`，复习时优先复习该调。

### 场景 7 · 诺诺聊天 → 从陪聊升级为教学陪练（已有，强化 + 闭环）
- **现在**：`nonoChatReply`(L4494) 请求体 `{uid,hist,text}`，纯通用陪聊，无教学系统提示、无与评分/复习联动。
- **大模型进**：请求体加 `role`（「教老外学中文的教练，用简短中文+母语提示纠正」）与 `weak`（从 `state.aiWeak` 注入用户常错点）；聊天中纠正的点实时写回 `state.aiWeak`。
- **闭环**：聊天 → 评分 → 复习 → 字卡 五处共享同一个 `state.aiWeak` 账本，形成「指出一次、处处优先练」的全局闭环。

### 横向 · 反馈/埋点 → 让 AI 反馈进账本 + L3 可见 + L4 聚合  ✅ **L4 已落地 v0.23.18**
- **L4 落地形态（v0.23.18）**：不新增 KV 写，后端 `_worker.js` 加 `GET /api/agg`（STATS_TOKEN 保护）+ `aggregateAiEffect` 游标分页聚合 `p:` 全量 profile 镜像（devices / D1-returned（≥2 天且跨度≥1d）/ aiUsers（aiFunnel.hit>0）/ hit / loop / loopRate / weak（aiWeak 维度求和），CAP 2000，零写）→ 把 L4「不可知」变为「可证伪」。注：原计划的「扩展 api/feedback 结构化事件」为更重形态，本期以「读时聚合已上云的 p: 镜像」达成同等可证伪目标，零额外写配额。

## 四、两条「接线」铁律（确保不做砸，来自技能落地篇）

1. **形态：单一追加块 + 全包装，主链零改动**
   - 所有新代码塞进一个 `<!-- ===== SINOKY_AI_WEAVE_BLOCK ===== -->` 哨兵块，插 `</body>` 前。
   - 只包装不改写：`var _orig = nonoGrade; nonoGrade = function(){ ... _orig.apply(this,args); }`，`try/catch` 内只 `console.error`，**绝不打断主流程**。

2. **幂等补丁：哨兵「先删后插」+ 吃干净换行** —— 连续重跑 3 次字符增量恒为 `+0`。

3. **独立渲染槽**：每个 AI 能力用自己的 class 槽（`.ai-weave-gop` / `.ai-weave-para` / `.ai-weave-tip`），不蹭 `nonoGrade` 原本重写的 `.np-fix` 槽（防互相冲掉）。

4. **三件通用件（几乎必做）**：
   - **入口级指令改写**：统一多语言/多角色，默认语言原样透传 ⇒ 主用例零行为变化，风险最低。
   - **分级超时 + 短指令重试**：`{short,normal,long}` 三档；`Promise.race([real,guard])` 保证必 settle；重试路径也要套闸门。
   - **同 key 结果缓存（读+写）**：修「只写不读」式死缓存，用 in-flight 去重防并发重复请求。

5. **让 AI 结果影响下一步行为**（最高价值）：核心是 `state.aiWeak` 独立账本，排序规则分层可解释（AI 点名优先 → 原排序 → 难度方向 → 稳定）。

## 五、为什么这叫「极致」（核心论证，逐条可反驳）

1. **极致 = 可被验证，不是机制堆叠。** 方案把「修 L3 可见性」列为 P0 并与铺模型同步——没有它，「大模型渗透率从 1 家族→7 家族」只是内部数字，无法证明用户多学会了。可验证性，是极致与「堆功能」的分水岭。

2. **极致 = 铺在用户花时间的地方。** 审计证明：用户意志力花在开口练习（跟读/复习/场景/每日一句/字卡/声调），而原大模型只在闲聊。本方案把模型挪进 7 个练习场景，让每一分钟练习都被 AI 个性化——这是「接对地方」的极致。

3. **极致 = 闭环，不是气泡。** 7 个场景共享一个 `state.aiWeak` 账本：聊天指出 → 评分确认 → 复习优先排 → 字卡生成辨析 → 声调解释。**AI 说一次，全产品下次必练**。这是「接了线且线通电」的极致。

4. **极致 = 免费模型榨干。** 一个 `/api/chat` 端点（GLM-4-Flash，边际成本≈0）服务 7+ 场景，不引入任何付费模型、不新增基础设施——在「白嫖优先」约束下做到全覆盖。

5. **极致 = 安全可灰度。** 追加块 + 钩子策略保证：钩子未注入时行为与改造前逐字一致，可安全灰度、可一键回滚；静态护栏（`_checks_*.py` 哨兵 + 能力入口函数名 + 关键常量）防止整块被覆盖。

6. **极致 = 直面「自己都连错四轮」的反证。** 审计者通读项目记忆仍连错四轮才摸清边界 → 真实用户面对 179 入口会怎样？本方案给每个 AI 能力一个**可验证落点 + 运行时抓包验收**，把「自我感动式智能化」彻底堵死。

7. **极致 = 先解决「有多少人在用」。** 依记忆 n=27 设备时，任何产品改动效果≈噪声、期望收益≈0。方案第一步修 L3，让「极致」先有度量基础，再谈渗透——顺序错了，极致就成空话。

## 七、验收清单（再审计篇五步，杜绝「50% 失效」写成「100% 完成」）

```
① 广度：三列矩阵（直连 / 运行时接线 / 仅间接）+ 与审计基线对比（1 家族 → 7 家族）
② 深度：闭环链路追踪 —— AI 结果是否真写回 state.aiWeak / 改变 revQueue 排序 / 落盘展示
③ 一致性：运行时抓包（mock fetch 记录 body）—— 每个出口发出的请求体是否残留硬编码语言假设
④ 能力利用度：每个能力的中枢调用点数，标出「仅 1 处」的孤岛
⑤ 参数质量：maxTokens 分布 / 分级超时覆盖 / 同 key 缓存命中率
```
**核心心法**：「接了线」和「线通电」是两件事。报告必须同时给出两个数字——否则会把「部分失效」写成「全部完成」。
