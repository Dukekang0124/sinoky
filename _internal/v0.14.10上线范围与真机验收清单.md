## 二、APK 打包与输出方式

### 2.1 打包链路（全自动，tag 触发）

```
git push tag v0.14.10
   └─ GitHub Actions（.github/workflows/apk.yml）
        ├─ Node 22 + Capacitor 同步 www/ → Android 工程
        ├─ gradle assembleRelease（release keystore 三文件来自仓库 secrets）
        └─ 产出签名包 Sinoky-v0.14.10-release.apk
             ├─ ① 推 dist 分支（取包兜底通道）
             ├─ ② 发布到 Pages：https://sinoky.pages.dev/apk/Sinoky-v0.14.10-release.apk
             └─ ③ 回写 main 的 version.json：apk.md5 / apk.size（[skip ci] 提交）
   └─ 我方收尾：拉取 CI 元数据 → 下载线上真包校验 md5 → 回填 main 的 apk/ 目录（只留最新版）→ push 触发最终 Pages 部署 → 生产终验
```

**为什么必须回填**：Pages 每次部署都是「仓库根全树」快照。若不把真包与真实 md5 随 main 走，最终那次部署会把 version.json 里的 apk 字段覆盖成空值 → 应用内更新会报 `size mismatch` 而失败。

### 2.3 你拿到包的三个入口（任选）

1. **App 内「检查更新」** —— versionCode `1410 > 1409`，会自动弹更新提示
2. **下载页** —— https://sinoky.pages.dev/download
3. **直链** —— https://sinoky.pages.dev/apk/Sinoky-v0.14.10-release.apk
