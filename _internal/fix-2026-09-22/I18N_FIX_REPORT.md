# Sinoky i18n 全中文缺口修复报告（v0.23.14，仅网页发布）

> 基准：v0.23.13（修复前）。本文档对应 commit `a52759f`（已 push 到 `main`）。
> 配套脚本：`scan_i18n_v1.py`（四分类扫描）· `triage_s1.py`（UI 语境中文提炼）· `patch_i18n_v1.py`（71 条补丁）· `merge_i18n_v1.py`（75 键 ×6 语言字典合并）· `verify_i18n_runtime.cjs`（7 语言运行时验收）· `verify_views_regression.cjs`（16 视图双语回归）。

## 一、问题来源（实锤）

用户提供截图：产品整体为英文界面，但弹出的「接一句」模态框**整框中文**（标题「接一句 💬」、提示「你刚说了…换一个词，说一句你自己的…」、按钮「🎤 我来改一句 / 跳过 / 完成」）。
说明：v0.23.13 及更早版本中，大量**面向用户的 UI 文案**仍硬编码中文或英文原文，未走 `T()` 翻译层 —— 非中文语种（西/俄/越/印尼/泰）界面会看到中文或英文。这是真缺口，必须修。

## 二、排查口径（关键：区分「真缺口」与「学习内容本体」）

产品内大量中文是**学习材料本身**，不是 UI 文案，不能翻：
- 场景句型（如「你好」「我要一瓶水」）、拼音拆解（`你:nǐ|好:hǎo`）、声调标注、城市名（北京/上海）、场景分类标题（`Food · Order & pay`）——这些是用户来学的内容，保留原文是产品定位。
- 少部分是**中英双语教学提示**（如「看懂了，也要说出来」），中文行是教学内容、英文行是指令，刻意双语，保留。

真缺口 = **界面外壳文案**（按钮、弹窗、报错、额度卡、提示语）被写死成某一种语言。本报告只修真缺口。

扫描器四分类：
- **S1** 裸中文（未 T()）：1483 条中绝大多数是学习材料；经 `triage_s1.py` 提炼出 UI 语境中文 73 条 → 本次修 43 条，保留 30 条（双语教学提示）。
- **S2** `T()` 字面量 ×6 字典缺失：**修复后 0 条**（字典已补齐）。
- **S3** 裸英文写 DOM 且无 key：128 → 117；剩余 117 条绝大多数是场景/城市英文标题（内容本体），保留；UI 类英文已补 T()。
- **S4** 静态区 CJK 文本节点 9 条（双语教学提示 + 「更多语言陆续支持」），转义泄漏 0 条。

## 五、保留项（刻意不翻，非缺口）
